# Architecture Deep Dive

Details that don't fit in the top-level README: the exact training pipeline, hyperparameters, ensembling logic, data schema, and known limitations.

## Data

Both `TrainingDataset.csv` and `ValidationDataset.csv` share the same schema: 11 physicochemical measurements per wine, plus a quality label.

| Column | Type | Notes |
|---|---|---|
| fixed acidity, volatile acidity, citric acid, residual sugar, chlorides, free sulfur dioxide, total sulfur dioxide, density, pH, sulphates, alcohol | numeric | cast to `double` and assembled into a single `features` vector |
| quality | integer (1-10) | renamed to `label`; treated as a 10-class classification target, not a regression target |

## Training pipeline (`training/winePrediction_model.py`)

Runs as a Spark job on the EMR cluster. Steps, in order:

1. **Load & cast**: both CSVs are read with schema inference, then every column is cast to `double` and `quality` is renamed to `label`.
2. **Preprocessing pipeline** (fit on training data only, then reused for validation/test):
   - `VectorAssembler`: combines the 11 feature columns into a single `features` vector
   - `StandardScaler` (`withMean=True`, `withStd=True`): zero-centers and unit-scales the features into `scaledFeatures`
3. **Class weighting**: wine quality is heavily imbalanced — most wines score 5 or 6, very few score at the extremes. A weight is computed per class as `total_count / count(label)` and broadcast to all executors, then applied as a per-row `classWeight` column so the RandomForest's `weightCol` parameter can down-weight the majority classes during training.
4. **Train 3 RandomForest classifiers** on the same weighted, scaled training data, with different hyperparameters:

   | Model | numTrees | maxDepth | maxBins | minInstancesPerNode | seed |
   |---|---|---|---|---|---|
   | rf1 | 200 | 10 | 32 (default) | 1 (default) | 42 |
   | rf2 | 200 | 10 | 64 | 1 | 423 |
   | rf3 | 200 | 10 | 96 | 1 | 17 |

5. **Evaluate** each model independently on the validation set using `MulticlassClassificationEvaluator` (F1 metric).
6. **Save 4 artifacts** to the given output path: `preprocess/`, `rf_model_1/`, `rf_model_2/`, `rf_model_3/`.

## Ensemble inference (`prediction/winePrediction_application.py`)

1. Loads the test CSV, applies the *same* saved preprocessing pipeline (not refit).
2. Loads all 3 saved RandomForest models and generates one prediction per row from each.
3. **Combines the three predictions via `majority_vote`**:
   - If any class got ≥2 of the 3 votes, that class wins.
   - If all three models disagree (no majority), the final prediction is the **rounded average** of the three predictions.
4. Prints a sample of predictions from all 3 models plus the ensemble result, and (if labels are present) computes the ensemble F1 score.

This ensembling approach is a form of bagging across independently-seeded models with slightly different tree-splitting parameters (`maxBins`), intended to reduce variance compared to any single RandomForest.

## Docker packaging

The `Dockerfile` in `prediction/` uses `python:3.10-slim` as a base, installs `default-jdk-headless` (required for PySpark's JVM backend), installs `pyspark`/`numpy`/`pandas`, and copies in the prediction script plus the trained model directory (`winePrediction_model_ensemble/`, expected to already exist alongside the Dockerfile at build time — see the README's Getting Started section). `entrypoint.sh` takes a single argument (the path to a test CSV, expected to be mounted into the container via `-v`) and invokes `winePrediction_application.py` against the model directory baked into the image.

## Known issues / changes since the original submission

- **Fixed a model-path mismatch.** The `Dockerfile` copies the trained model directory in as `/app/winePrediction_model_ensemble`, but the `entrypoint.sh` originally submitted for grading pointed at `/app/wine_rf_three_fixed` — a path the Dockerfile never actually created. As submitted, a fresh `docker build` + `docker run` would have failed at runtime with a "path not found" error when loading the model. This repository's `entrypoint.sh` has been corrected to reference `/app/winePrediction_model_ensemble`, matching what the Dockerfile actually copies in and what the rest of the documentation consistently refers to.
- **The trained model artifacts are not included in this repository** (`models/` and `winePrediction_model_ensemble/` are gitignored) — they're a few hundred MB of Spark model output regenerated by running the training step, not source code. Build the Docker image only after training and copying the model folder into `prediction/` per the README.

## Known limitations

- **Hyperparameters were hand-picked**, not tuned via `CrossValidator` or grid search — the three `maxBins` values (32/64/96) were chosen to add ensemble diversity rather than being independently optimized.
- **Quality is treated as 10 unordered classes.** A multiclass classifier doesn't know that a true score of 6 is "closer" to a prediction of 7 than to a prediction of 2 — an ordinal-regression approach or a regression-then-round approach might perform better on this kind of ordered label, at the cost of losing MLlib's off-the-shelf multiclass tooling.
- **No hyperparameter or feature-importance analysis is persisted** — the training script prints per-model F1 scores to the driver log but doesn't save them alongside the model artifacts, so historical comparisons require re-reading old logs.
